# EOR3 延迟探针(STEP 0)

判断 SHA3 扩展的 `EOR3`(三路异或)与普通 `EOR` 是否同延迟。
`hash_neon` 用 `VEOR3` 缩短依赖链的整个收益都押在「同延迟」这个假设上:

| EOR3 延迟 | 预计收益 |
|---|---|
| = EOR(1 层) | 5–8% |
| 1.5 层 | ~6%,勉强 |
| 2 层 | **归零,而指令多 25% —— 纯亏** |

## 跑法

    go run .

## 设计

- 三条严格串行的依赖链:100×`VEOR`、200×`VEOR`、100×`VEOR3`,每条都以 `V0` 既作源又作目标
- `V1`/`V2` 预置非零,避开「同寄存器异或」这种断依赖惯用法
- 交错测量、逐轮换序、取最小值(慢尾是干扰不是被测代码)
- **有效性闸门**:200 链与 100 链的每-op 时间必须一致(0.95–1.05)。不一致说明测的不是延迟,直接 `exit 1` 拒绝报告比值 —— qemu 下就会正确地不通过
